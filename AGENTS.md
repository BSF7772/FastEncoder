## Project overview
FastEncoder is a native Windows 11 app (C# · WinUI 3 · Mica) that shrinks videos with ffmpeg while keeping quality, with trim,
volume, speed, audio-sync detection and size estimates. Product intent, in the maintainer's words:

> fast encoder that very optimize video files and compress their size. with basic options like trim, adjust volume, and increase
> speed. basic ui that save settings with native windows ui or similar that just work. no web.

`src/Core` is also compiled into **SteamPoweredPlayer** (as a git submodule), so its public API is shared. Keep Core free of UI
code, and treat signature changes in `Ff`, `Encoders`, `Presets`, `Pipeline` and `AudioSync` as breaking.

## Commands
```powershell
FastEncoder.bat                       # build on first run, then start
FastEncoder.bat --rebuild             # rebuild after source changes
dotnet build src\FastEncoder.csproj -c Release -nologo
src\bin\x64\Release\net10.0-windows10.0.22621.0\win-x64\FastEncoder.exe --selftest report.txt     # exit 0 = all PASS
src\bin\x64\Release\net10.0-windows10.0.22621.0\win-x64\FastEncoder.exe --syncdetect video.mp4 report.txt
```
Requires the .NET 10 SDK and ffmpeg/ffprobe on PATH.

## Tech stack
C# (latest) / .NET 10 (`net10.0-windows10.0.22621.0`, x64), WinUI 3 via Windows App SDK 1.8 (unpackaged, self-contained WinAppSDK),
nullable + implicit usings enabled. ffmpeg/ffprobe run as external processes. Encoders: SVT-AV1 10-bit + Opus (CPU),
NVENC/QSV/AMF (GPU, each proven by a test encode before it's offered), x264.

## Project structure
```
src/Core/Ff.cs          ffprobe/ffmpeg process helpers, probing, frames, filmstrip
src/Core/Encoders.cs    encoder catalog + GPU detection
src/Core/Presets.cs     storage presets (Balanced, Archive, Pristine, GPU Turbo, Compact 720p, Universal, Fit to size, Trim only)
src/Core/Pipeline.cs    command building, encode, estimate, proxies
src/Core/AudioSync.cs   A/V offset detection (sound ↔ flash/impact matching)
src/Core/SelfTest.cs    --selftest / --syncdetect
src/Core/AppSettings.cs settings (%LOCALAPPDATA%\FastEncoder\settings.json) · src/Core/Taskbar.cs taskbar progress
src/MainWindow.xaml(.cs) UI · src/JobItem.cs queue item model · src/App.xaml(.cs) entry + CLI switches
```

## Code style
- Core: no UI types; `async` + `CancellationToken` for anything that runs ffmpeg; invariant culture for every number passed to ffmpeg.
- UI: FastEncoder's design language (Mica, `Card` style, brand gradient #7C3AED→#2563EB→#06B6D4, emoji preset tiles, staggered
  entrance transitions); work off the UI thread, then marshal back with `DispatcherQueue`.
- Small, focused changes; match the surrounding code.

## Testing
- `--selftest` must pass (every preset, CPU two-pass/scale paths, audio sync: 300 ms injected must be detected and fixed, jittery
  capture must come out at an even rate). Add a self-test case for every new preset or pipeline path.
- Test media is generated by the self-test. Never commit videos.

## Git workflow
- Branch `main`; conventional commits (`feat:`, `fix:`, `docs:`, `test:`). Run the build and `--selftest` before committing.
- A change to the shared Core must keep SteamPoweredPlayer building; that repo pins this one as a submodule and bumps it deliberately.

## Boundaries
- ✅ **Always:** keep Core UI-free, keep settings in `%LOCALAPPDATA%\FastEncoder`, clean up only FastEncoder's own temp folder.
- ⚠️ **Ask first:** new dependencies, changes to preset definitions or the shared Core API, bundling ffmpeg binaries.
- 🚫 **Never:** commit secrets, personal data (real paths, hostnames, IPs, account names, hardware details of a developer's
  machine) or media files; install anything system-wide; bypass git hooks with `--no-verify`.
